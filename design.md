# Polyform System Architecture & Specification (design.md)

## 1. Architectural Overview & Invariants

Polyform is the canonical Axiomantic polyglot megatemplate. It synthesizes pure Nim, TypeScript WebAssembly, Python native wheels, and HeaderKit C/C++ FFI bindings into a unified, battle-tested generator engine.

### 1.1 Core Invariants
1. **Separation of Generator & Generated (`_subdirectory: template`)**:
   Polyform repo-internal development tooling (root CI, fixture tests, documentation, task runners) lives exclusively at the repository root and is never leaked downstream. All rendered project files reside within `template/`.
2. **Upstream Linkage Invariant (`.copier-answers.yml`)**:
   Every downstream repository generated by Polyform records its configuration in `.copier-answers.yml`. Projects maintain an active link to upstream template tags, enabling non-destructive `copier update` migrations.
3. **Dual Entrypoint Reference Parity**:
   Generating a project via terminal CLI (`uvx copier copy gh:axiomantic/polyform <dst>`) and generating via GitHub Web UI ("Use this template" -> automated `bootstrap.yml`) produce byte-for-byte and behaviorally identical repositories.
4. **Canonical Command Surface (`justfile`)**:
   Every generated repository, regardless of flavor, exposes the standard Axiomantic command surface: `just setup`, `just test`, `just lint`, `just fmt`, `just docs`, `just docs-build`, and `just build`. Developers interact with `just`, never memorizing toolchain-specific invocation incantations.
5. **Zero Dead Code & Zero Stubs Invariant**:
   Conditional files for inactive flavors are strictly excluded via Jinja rules. No unused shims, comments, or inactive scaffolds are left behind.
6. **Formatting Authority**:
   `nph@0.7.0` is the single formatting authority across Nim source files, enforced via `.pre-commit-config.yaml` and CI.
7. **Immediate Out-of-the-Box Verifiability (No Green Mirage)**:
   Every generated flavor passes `just setup`, `just lint`, and `just test` immediately upon rendering without requiring manual shims or missing compiler toolchains.

## 4. Dual Entrypoint Mechanics

### 4.1 CLI Entrypoint (`uvx copier copy`)
The CLI provides immediate interactive feedback:
```bash
uvx copier copy gh:axiomantic/polyform my-cool-project
```
Copier prompts the user through the questions defined in `copier.yml`, validates input against regex patterns, renders the selected flavor, and executes `git init`.

### 4.2 GitHub Web UI Auto-Hydration (`.github/workflows/bootstrap.yml`)
When a user clicks "Use this template" in GitHub, GitHub copies the repo verbatim without rendering Jinja. The downstream repository wakes up on its initial push with the self-deleting hydration workflow:

```yaml
name: Polyform Auto-Hydration
on:
  push:
    branches: [main, master]
permissions:
  contents: write

jobs:
  hydrate:
    # Only run on newly spawned repositories, never on polyform template itself
    if: github.repository != 'axiomantic/polyform' && hashFiles('copier.yml') != ''
    runs-on: ubuntu-latest
    steps:
      - name: Checkout Repository
        uses: actions/checkout@v4
        with:
          token: ${{ secrets.GITHUB_TOKEN }}
          fetch-depth: 0

      - name: Install uv & Copier
        uses: astral-sh/setup-uv@v5
        with:
          enable-cache: true

      - name: Derive Project Metadata
        id: meta
        run: |
          REPO_OWNER="${GITHUB_REPOSITORY%/*}"
          REPO_NAME="${GITHUB_REPOSITORY#*/}"
          REPO_SLUG="${REPO_NAME//-/_}"
          echo "owner=${REPO_OWNER}" >> "$GITHUB_OUTPUT"
          echo "name=${REPO_NAME}" >> "$GITHUB_OUTPUT"
          echo "slug=${REPO_SLUG}" >> "$GITHUB_OUTPUT"

      - name: Render Template In-Place
        run: |
          # Render template to temporary staging directory
          uvx copier copy --trust --defaults \
            -d project_name="${{ steps.meta.outputs.name }}" \
            -d repo_name="${{ steps.meta.outputs.name }}" \
            -d package_name="${{ steps.meta.outputs.slug }}" \
            -d github_owner="${{ steps.meta.outputs.owner }}" \
            -d flavor="pure_nim" \
            -d docs_engine="starlight" \
            . /tmp/hydrated

          # Clear unhydrated template files from workspace
          git rm -rf template/ copier.yml .github/workflows/bootstrap.yml tests/

          # CRITICAL FIX: Purge staging .git directory to prevent corrupting active repository git
          rm -rf /tmp/hydrated/.git

          # Copy rendered files into workspace root
          cp -a /tmp/hydrated/. .

          # Ensure .copier-answers.yml records upstream remote (portable across GNU/BSD)
          python3 -c "import pathlib, re; p = pathlib.Path('.copier-answers.yml'); p.write_text(re.sub(r'_src_path: .*', '_src_path: gh:axiomantic/polyform', p.read_text()))"

      - name: Commit Hydration & Self-Delete
        run: |
          git config user.name "github-actions[bot]"
          git config user.email "41898282+github-actions[bot]@users.noreply.github.com"
          git add -A
          git commit -m "chore: hydrate repository from polyform template [skip ci]"
          git push origin HEAD
```

**Idempotency & Self-Deletion Invariant**:
By removing `.github/workflows/bootstrap.yml` and `copier.yml` in the very same commit that hydrates the project, subsequent git pushes will never execute hydration again.

## 5. Unified Command Surface (`justfile` Contract)

The `justfile` is the single source of truth for developer operations. Each flavor implements the standard recipes to conform with the Axiomantic contract:

```just

default:
    @just --list

# 1. Dependency Setup
setup:
    {% if flavor == 'nim_ts_wasm' %}
    npm install
    nimble install --depsOnly -y
    {% elif flavor == 'nim_python_wheel' %}
    uv pip install -e ".[test]"
    nimble install --depsOnly -y
    {% else %}
    nimble install --depsOnly -y
    {% endif %}

# 2. Test Suite Execution
test:
    {% if flavor == 'nim_ts_wasm' %}
    nimble test
    npm run test
    {% elif flavor == 'nim_python_wheel' %}
    nimble test
    pytest tests_py/
    {% else %}
    nimble test
    {% endif %}

# 3. Linter Execution
lint:
    nph --check
    nimble check
    {% if flavor == 'nim_ts_wasm' %}

    nph
    {% if flavor == 'nim_ts_wasm' %}
```

## 6. Upstream Continuous Upgrade Protocol (`copier update`)

When improvements, security fixes, or new CI workflows are added to `axiomantic/polyform`, downstream repositories update seamlessly:

```bash
cd my-project
uvx copier update --trust
```

### 3-Way Merge Mechanics
1. Copier reads `_commit` and answers recorded in `.copier-answers.yml`.
2. It checks out the previous template commit and the latest template tag.
3. Copier renders both commits with the project's saved answers.
4. Using `git merge-file`, Copier applies the delta between template versions onto the downstream repository.
5. User modifications to source files (`src/`, `tests/`) are preserved cleanly, while boilerplate and tooling updates are merged.

## 7. Polyform Root Verification Harness (`tests/test_fixtures.sh`)

To eliminate the "Green Mirage" and guarantee that the megatemplate never produces broken repositories, Polyform includes an automated fixture verification suite:

```bash
#!/usr/bin/env bash
# tests/test_fixtures.sh
set -euo pipefail

SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
REPO_ROOT="$(cd "${SCRIPT_DIR}/.." && pwd)"

FLAVORS=("pure_nim" "nim_ts_wasm" "nim_python_wheel" "headerkit_binding")
FIXTURE_DIR="$(mktemp -d /tmp/polyform-fixtures-XXXXXX)"
trap 'rm -rf "${FIXTURE_DIR}"' EXIT

echo "=== [POLYFORM HARNESS] Starting Fixture Verification ==="
echo "Working directory: ${FIXTURE_DIR}"

for FLAVOR in "${FLAVORS[@]}"; do
  echo ""
  echo ">>> [TEST] Rendering Flavor: ${FLAVOR} ..."
  DEST="${FIXTURE_DIR}/${FLAVOR}"
  
  uvx copier copy --trust --defaults \
    -d project_name="fixture_${FLAVOR}" \
    -d repo_name="fixture-${FLAVOR}" \
    -d package_name="fixture_${FLAVOR}" \
    -d flavor="${FLAVOR}" \
    -d docs_engine="starlight" \
    "${REPO_ROOT}" "${DEST}"

  echo ">>> [VERIFY] Checking .copier-answers.yml presence ..."
  test -f "${DEST}/.copier-answers.yml"

  echo ">>> [SETUP] Running just setup on ${FLAVOR} ..."
  (cd "${DEST}" && just setup)

  echo ">>> [VERIFY] Running just lint on ${FLAVOR} ..."
  (cd "${DEST}" && just lint)

  echo ">>> [VERIFY] Running just test on ${FLAVOR} ..."
  (cd "${DEST}" && just test)

  echo ">>> [PASS] Flavor ${FLAVOR} successfully verified!"
done

echo ""
echo "=== [POLYFORM HARNESS] ALL FLAVORS PASSED THREE-KEY GATE VERIFICATION ==="
```

## 8. Phasing & Implementation Strands

The migration of `template-nim` to `polyform` is structured into 4 isolated Vine strands:

1. **Strand 1 (`strand/copier-core-scaffold`)**:
   - Create root `copier.yml` with schema, question prompts, conditional `_exclude` rules, and tasks.
   - Establish `template/` payload directory.
   - Migrate baseline files into `template/` with `.jinja` extensions.
   - Implement `template/.copier-answers.yml.jinja`.
2. **Strand 2 (`strand/polyglot-flavor-matrix`)**:
   - Implement Flavor B (`nim_ts_wasm`): `package.json.jinja`, `tsconfig.json.jinja`, `ts/`, `vitest.config.ts.jinja`, `compile_wasm.sh.jinja`.
   - Implement Flavor C (`nim_python_wheel`): `pyproject.toml.jinja`, `CMakeLists.txt.jinja`, `src_py/`, `tests_py/`, `cibuildwheel.yml.jinja`.
   - Implement Flavor D (`headerkit_binding`): `headerkit.toml.jinja`, `include/`, `src/{{ package_name }}/bindings.nim.jinja`, `scripts/generate_bindings.py.jinja`.
3. **Strand 3 (`strand/dual-entrypoint-bootstrap`)**:
   - Implement self-deleting `.github/workflows/bootstrap.yml`.
   - Remove obsolete `template-cleanup.yml`.
   - Update repository `README.md` and `AGENTS.md` for Polyform branding.
4. **Strand 4 (`strand/verification-harness-ci`)**:
   - Implement `tests/test_fixtures.sh`.
   - Update root `justfile` with Polyform test and lint recipes.
   - Update root `.github/workflows/ci.yml` to run `tests/test_fixtures.sh` across the matrix.

## 9. Antithesis Resolution & Synthesis Matrix (Step 2.3)

| Defect ID | Severity | Antithesis Finding (@polyform-auditor) | Synthesized Architectural Remediation |
|---|---|---|---|
| **CRIT-01** | CRITICAL | Bootstrap `.git` overwrite hazard: In `bootstrap.yml`, copying `/tmp/hydrated/.` into root risks overwriting active repo `.git` if `_tasks` ran `git init`. | 1) `copier.yml` `_tasks` guarded with `test -d .git \|\| git init -q`.<br>2) `bootstrap.yml` explicitly executes `rm -rf /tmp/hydrated/.git` before `cp -a /tmp/hydrated/. .`. |
| **CRIT-02** | CRITICAL | Fixture test dependency hydration gap: Fresh fixtures rendered in `/tmp` fail `just test` because dependencies (npm, pip/uv) are never installed. | 1) Canonical `just setup` recipe added to `justfile.jinja`.<br>2) `tests/test_fixtures.sh` executes `just setup` prior to `just lint` and `just test`. |
| **WARN-01** | WARNING | Conditional docs recipes when `docs_engine == 'none'`: Calling `just docs` crashes when documentation engine is omitted. | `docs` and `docs-build` recipes in `justfile.jinja` are conditionally wrapped inside `{% if docs_engine != 'none' %}` blocks. |
| **WARN-02** | WARNING | Flavor D out-of-box tripwire: Freshly generated Flavor D packages fail `just test` if foreign C symbols or bindings are missing. | `include/{{ package_name }}.h.jinja` and matching `src/{{ package_name }}/bindings.nim.jinja` provide a complete baseline C symbol and binding so `test_tripwire.nim` compiles and passes out of the box without external generator runs. |
| **DOC-01** | INFO | Portability of `sed -i` in bootstrap workflow: BSD vs GNU sed syntax differences cause workflow failures on macOS. | Replaced `sed -i` with portable `python3 -c "import pathlib, re; ..."` across workflow definitions. |
